# Contract Layer — Subscription Health Data Product

_Generated by `scripts/build_contracts.py` from `contracts/consumers.yaml` and
`contracts/schemas/*.yaml` (register v0.1.0, last reviewed 2026-10-23).
Do not edit by hand._

The contract layer sits between the warehouse models (ADR-001, dbt), the
orchestrator's asset checks (ADR-002) and the micro-batch event feed (ADR-003) on one
side, and the three consumers on the other. Every contract is validated against those
ADRs, the security matrix and the assumptions register, and it generates the physical
schema the spec uses:

- `contracts/generated/dbt/snowflake/schema.yml`
- `contracts/generated/dbt/bigquery/schema.yml`
- `contracts/generated/jsonschema/raw.subscription_events.schema.json`

## 2. Consumer contracts

### CON-RET: Retention team

Works the daily at-risk list at the morning stand-up and monitors churn and promo-day cancellations intraday.

**Reads:** `marts.retention_subscription_health_daily`, `marts.retention_events_hourly` · **Roles:** retention_analyst, retention_agent · **Purposes:** P5 · **Max classification:** C2

**SLA:** Daily mart by 07:00 local (A-OPS-02); hourly aggregate typically ~1 h behind, at most 90 min (ADR-003).

**On breach:** Dashboards keep the last good partition with a stale banner showing its as-of time; the data-product owner is alerted at the first miss and the on-call engineer is paged after two consecutive daily misses.

**Guarantees:**

- One row per subscriber per day; no duplicates (GR-RET-03).
- No direct identifiers; subscriber_id is a surrogate key (C2).
- Subscribers who objected to analytics or requested deletion are excluded (GR-RET-05).
- Intraday aggregates suppress cells under 10 subscribers (ABAC-08).

**Change policy:** Additive columns ship without notice. Removing or renaming a column, or adding a subscription_status level, is breaking: 30 days' notice and a new contract version. Breaking changes approved by: Retention team lead, Lead Analytics Engineer.

### CON-ML: ML team (churn-risk model)

Trains the churn-risk model on historical feature snapshots and scores all active subscribers nightly.

**Reads:** `features.churn_features` · **Roles:** ml_engineer · **Purposes:** P5 · **Max classification:** C2

**SLA:** Nightly partition by 07:00 local (A-OPS-02); open-format snapshot available for training reads (ADR-001).

**On breach:** Scoring reuses the previous day's scores and ML on-call is alerted. Two consecutive misses block scoring and page; the retention mart then shows scores with their as-of date.

**Guarantees:**

- Point-in-time correct; no feature uses data after feature_date.
- Stable columns keep name, type and meaning within a major version.
- Late events within the 3-day window (A-OPS-03) are reprocessed; older partitions are immutable.
- Objecting or deletion-pending subscribers never enter features or labels (GR-FEA-05).

**Change policy:** Changes to any stable column create a new version (churn_features v2) published side by side with v1 for at least 60 days. Agent-authored changes to stable fields need the ML Engineering lead's named approval (ADR-004 Zone 2). Breaking changes approved by: ML Engineering lead.

### CON-RAG: Retention-support assistant (RAG)

Retrieves redacted transcript chunks to draft answers for retention staff (ADR-004 Zone 1). Never customer-facing; never takes account actions.

**Reads:** `rag.transcript_chunks` · **Roles:** svc_retention_assistant · **Purposes:** P8 · **Max classification:** C3

**SLA:** Chunks for tickets closed by end of the previous day, by 07:00 local; staleness of a few days is tolerated.

**On breach:** The assistant keeps serving the existing index; after three consecutive misses it labels answers as possibly outdated. A PII or consent failure withholds the affected chunks from the index; it never degrades to indexing unchecked text.

**Guarantees:**

- Every chunk passed PII scanning after redaction (GR-RAG-03).
- Only subscribers in scope for AI processing, and only after SEC-G3 clears (GR-RAG-05).
- Deleted subscribers' chunks leave the table and the index within the deletion SLA (R-11, R-12).
- Chunks are at most 512 tokens (A-TRN-04).

**Change policy:** Changes to chunking or redaction bump redaction_version and trigger a full re-index reviewed at SEC-G6. Breaking changes approved by: ML Engineering lead, Privacy / Legal.

## 4. Governance rules as code

Implemented in `aurora_contracts/governance.py`, configured per dataset in
`contracts/schemas/*.yaml`, and tested in `tests/test_governance.py`. Each rule runs
as an orchestrator asset check (ADR-002): `ERROR` checks block publish, `WARN` checks
alert. Unknown consent state fails closed.

### Failure behaviors

| Failure behavior      | Blocking   | What happens                                                                                                                                           |
|:----------------------|:-----------|:-------------------------------------------------------------------------------------------------------------------------------------------------------|
| block_publish         | yes        | Blocking asset check fails; the batch is not published and consumers keep the last good version; owner alerted.                                        |
| quarantine_rows       | no         | Offending rows move to a restricted quarantine table with the rule ID; the rest publish. Escalates when the quarantined share passes the rule's limit. |
| serve_stale_and_alert | no         | Consumers keep the last good version with a stale banner showing its as-of time; owner alerted; escalates after N consecutive misses.                  |
| security_incident     | yes        | Batch blocked, offending rows quarantined for purge (R-04), security incident opened and Security lead paged.                                          |
| warn                  | no         | Batch publishes; non-blocking alert to the owner.                                                                                                      |
